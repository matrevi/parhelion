## 合入后发现（2026-11-26）

- **`opsb replay gate` 从正式入口直接崩溃**，报 `ModuleNotFoundError: No module named 'scheduler'`。
  - 原因：`cli/opsb` 只把 `cli/` 放进 `sys.path`，`gate_replay.py` 在函数里直接 `from scheduler ...`，没有先调 `config.ensure_scheduler_path()`。
  - 为什么没被发现：子代理与主会话的测试都带着 `PYTHONPATH=cli:.` 或 pytest 的仓库根，主会话合入时也没有按 RUNBOOK §3 在 main 上从真实入口重跑回放。
- **修复**：主会话在 `gate_replay.run` 开头调用 `ensure_scheduler_path()`，并加了回归测试 `test_real_entry_point_runs_without_pythonpath`：用子进程、不带 `PYTHONPATH`、在仓库外运行 `cli/opsb replay gate`。去掉修复时这条测试会失败。
- **修复后从真实入口重跑两场**，结果与报告一致：
  - ops-bench：4.2.1 拦 50/233，其中新高 18 发、带 next_step 6 发，restore 9/9，收官差额 10.19；
  - mat-chem：拦 66/78。
- **其他检查**：同批合入的其他新入口都从真实入口跑过，没有同类问题：
  - `opsb workspace rules`；
  - `opsb mcp list-tools` 的四种角色；
  - `parhelion_report(view=rules)`；
  - `parhelion_status` 的 judge 行。
