## Observations and proposed improvements

1. **DSH Desktop had no Parhelion tools** (fixed in 1192ce3). Registering a workspace is not
   enough; the profile must mount the MCP. Side effect: every open conversation in the folder
   spawns its own `opsb mcp serve`, and native subagents get the orchestrator role.
2. **The Token Notch overlay blocks the "New conversation" button.** Pointer events in the
   centre and right of the screen go to the overlay. Not a Parhelion bug, but the UI flow cannot be
   driven while it runs.
3. **Context grows fast from shell exploration.** Both orchestrator and workers spend their first
   tool calls on `cd`, `cat`, `ls` and `read`. The state card should carry what they look for
   (per-case ratios, recent receipts, the worktree path) so the first call is enough.
4. **The orchestrator derives per-case ratios by hand.** The status card should list per-case
   speedup against the same-generation baseline.
6. **CPU lane: compile -j1 is correct, case preparation is not.** `compile_lane` caps jobs at the
   number of translation units in `compile_commands.json`; template problems have one (`main.asc`),
   so -j1 and about 15 s of compile are inherent. The UI label "CMake 并发上限 -j1" reads like a
   throttle and should say "1 compile unit". Case preparation is the real cost: every run spawns one
   `reference_cases.py` per case, sequentially, and each one starts OpenBLAS with 32 threads (no
   `OPENBLAS_NUM_THREADS` cap, outside the compile budget). On the 32-core host two concurrent
   preparations ran 64 BLAS threads (load 11). Measured prep time per run (built → device batch,
   minus wait and hold): FFT3DBatchComplex ~50 s of a 107 s run, SgemmFp16Cube ~21 s,
   QuantScaleCalib ~13 s, NeighborListPbcFixedK ~9 s. Inputs and goldens come from the frozen
   oracle and do not depend on the candidate SHA, so they can be cached per oracle and case
   digest, and the remaining preparation should run with capped threads inside the CPU budget.
5. **Timing is noisy for tiny kernels.** Event timing jitters on sub-millisecond cases; the
   profiler path planned for 4.1 should replace it for gating.
7. **The S2 hold gate judges template problems on a commit-note guess.** The gate's
   `ScoreEstimator` reads only the legacy `validation.log` markers; for case-bench problems it
   finds "no perf telemetry" and falls back to the anchor or the commit note (sigma 5.68,
   trust 0.25). It then holds anything whose point estimate is below the 1.90-point floor
   "to preserve daily quota" while 140 of 150 daily slots are unused. The board keeps the best
   score (QuantScaleCalib latest 0 after WA, board 15.75), so a lower result costs only a slot.
   Of the two held candidates, one was a +5.78 breakthrough.

   Fixed in 599d8cc. The gate now pairs the candidate with the board SHA on the best warm
   minimum per official case over formal case-bench runs. It calibrates that projection on
   official receipts, replayed as of each submission time: the prior counts as three receipts,
   other problems count half. Bias, sigma and confidence move with the receipt count and the
   local evidence quality. Stage 2 passes when E[max(0, gain)] ≥ floor and P(gain > 0) ≥ 0.2;
   daily quota is not part of the threshold. Four receipts were available at once: NeighborList
   was over-predicted by 3.5 and 5.1 points, Edge by −1.1 and +0.7. A receipt that did not beat
   the board (score only in `timing_score`) was invisible to both the same-SHA history and the
   calibration; it now counts.
8. **An escape trial cannot be rebound before it is used.** `authorize_review_trial` binds one
   repair SHA per WA receipt and refuses any other, even when the bound SHA was never submitted
   and turned out incomplete. The worker had to stop and ask for an operator to delete the file.
   Allowing a rebind while the bound SHA has no submission keeps "one reviewed trial per WA"
   and removes the dead end.
9. **A per-case device budget turned a slow-I/O case into a permanent block.** The broker gave
   each case one deadline for its warmup and all timed repeats. FFT3DBatchComplex case 05 runs
   7.4 s per execution, so every candidate TLE'd locally on a case the judge passes, and the
   gate's Stage 1 rejected all of them as "exit_code=2". The budget now limits each execution,
   like the judge. Executions of 2 s or more stop after one warmup and two timed runs, since
   more repeats add no precision but hold the only device.
10. **Held cards said "missing precision record" for every Stage 1 block.** Escape locks and
   failed local runs looked like missing evidence. They now read ESCAPE LOCK, TEST FAILED (with
   the failing cases) or NOT TESTED.
11. **Review trials could chain.** Each WA opened a new escape lock, and each lock allowed one
   reviewed trial without a reproducer, so QuantScaleCalib went WA → trial → WA → trial → WA.
   A WA on a SHA that a reviewed trial released now requires a local reproducer. With zero
   local mismatches on all cases, the remaining Quant failure is data-dependent; the next step
   is to widen the local data (more seeds and tie-heavy inputs for the 2048×2048 mode-0 shape)
   until the bad SHA fails locally.
