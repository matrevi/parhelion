# P17 本地验证加固、逐例校准表与噪声感知判定（调研 R1 R2 R3）

分支：`impl/P17-verify-calibrate`。属于组 1，在 P07 之后做，依赖 P01 的 `scheduler/receipts.py` 与 `case_map.py`，以及 P02 的 final 级变体。

依据：`docs/v4.2/research/agent-optimization-practice.md` §3.2 与 R1–R3。调研的结论：
- 七个独立来源都显示，验证器加固之后，公开的加速比大幅缩水；
- 「叫模型不要这样做」无效，结构性措施才有效；
- 本地与评分端存在差距是常态，只能显式校准。

本场的现象与此吻合：本地零误差的候选线上 WA/RE。

## R1 让本地验证在结构上更严

1. **隔离与计时归属**：核对计时与同步完全由平台持有，候选代码无法导入或改写平台的计时、比对代码（`runtime/npu_runtime/*`、`npu-test.py`）。发现缺口就补上，并写单测。
2. **final 级别加随机化**：每次 final 运行在冻结 oracle 支持的参数范围内，派生 worker 看不到的值分布与形状变体。例如值域缩放 ×3、×0.01、×(−1)，以及未公开的形状。种子由运行 ID 确定性派生。与 P02 的 WA 变体共用变体机制，标记 `source="hidden-final"`。
3. **物理下限检查**：某个用例比解析的带宽或算力下限还快，或比该题此前最好成绩快一个可配置倍数（默认 3 倍，或超过历史最大提速的 2 倍），就标 `implausible`。
   - 被标记的结果不计入门禁证据，直到在冷启动会话中复测，且读数相差在 10% 以内。
   - 带宽下限需要每题的数据量与设备峰值带宽。峰值来自 `config.json` 的 device 段，仓库里不写数值；未配置时只做倍数检查。
4. **确定性 diff 筛查**：对候选相对基线的 diff 做规则检查，覆盖反复出现的几类模式：
   - 降低计算精度；
   - 以输入为键的缓存；
   - 按形状或 dtype 分支、只对测试形状走快路径；
   - `try`/`except` 回落到参考实现。
   
   命中时在门禁 S1 理由中提示，只提示，不自动拒绝。规则表放成数据文件，便于增补。

## R2 逐例的本地与评分端校准表

1. 每条规范回执都配对记录以下字段，持久化在 `results/<title>/.calibration-pairs.jsonl`，按 `submission_id` 去重：
   - 本地预测增量，相对同代基线；
   - 本地噪声带；
   - 评分端增量；
   - 所用基线。
2. 每例、每题计算：
   - 符号一致率与秩相关；
   - 回退率：本地为正、评分端为负的比例。
   
   每个用例据此标为 `trusted`、`noisy` 或 `divergent`。
3. 门禁返回预测分时附区间。只要涉及 `divergent` 用例，就在返回里标出来，并把这些用例的贡献按「未知」处理，即区间放宽，而不是当作 0。额度不进任何阈值。
4. 先用磁盘上已有的回执回溯计算一次，报告结果。

## R3 噪声感知的保留与判定

1. 逐例三态判定：配对增量超出该例噪声带一定余量（可配置，默认 1%）为 improved，反向为 regressed，其余为 indistinguishable。
   - 测试摘要、P12 的 `per_case` 视图和账本 `experiment.outcome` 都用这套三态。
   - 不要再把原始 µs 差值当作提升证据。
2. 重复样本的离散度（CV）超过阈值（默认 3%）的用例标 `noisy`，不计入增益声明，并在状态卡中标出。
3. P10 的 A/B 配对运行有数据时，噪声带取配对区间。

## 验收

- 单测：
  - 计时归属的隔离；
  - 隐藏变体的确定性与只在 final 生效；
  - 物理下限与倍数标记，以及冷启动复测解除标记；
  - diff 规则表各条的命中与不误报；
  - 校准表的去重与三类标签；
  - 门禁区间对 `divergent` 的处理；
  - 三态判定与 `noisy` 标记。
- 回溯报告：用现有回执算出校准表与标签，写入 `docs/plan-4.1-4.2/reports/P17-calibration.md`。附各题回退率，以及本场线上 WA/RE 的 SHA 在 diff 筛查下的命中情况。
- 真机：
  - 对一个已知通过的 SHA 跑一次带隐藏变体的 final，确认没有误报；
  - 对 QuantScaleCalib 的坏 SHA 跑一次，看隐藏变体能否额外暴露问题。
