# P17 本地验证可信度、逐例校准表与噪声感知判定（调研 R1 R2 R3）

分支：`impl/P17-v2`。属于组 1，从 `impl/P07-gate-queue` 切出，再合并最新的 `main`。依赖：
- P01 的 `scheduler/receipts.py` 与 `case_map.py`；
- P02 的 final 级变体机制。

依据见 `docs/v4.2/research/agent-optimization-practice.md` §3.2 与 R1–R3，这里只用它关于测量可信度的结论：
- 本地验证覆盖的输入越接近真实判题，本地结论越可靠；
- 本地与评分端存在差距是常态，必须显式校准。

本场的现象与此吻合：本地零误差的候选在线上 WA/RE。

> 2026-11-26 修订：原 R1 第 4 项「diff 规则筛查」已移出本包，暂不实施。

## R1 提高本地验证的可信度

1. **计时归属**：核对计时与同步完全由平台的运行时持有（`runtime/npu_runtime/*`、`npu-test.py`），候选代码只提供内核实现，不能改变平台的计时与比对逻辑。发现缺口就补上并写单测；没有缺口时，在报告中说明核对了哪些路径。
2. **final 级别增加未公开变体**：每次 final 运行，在冻结 oracle 支持的参数范围内，额外派生 worker 看不到的值分布与形状变体，例如值域缩放 ×3、×0.01、×(−1)，以及未公开的形状。
   - 种子由运行 ID 确定性派生。
   - 与 P02 的 WA 变体共用 `suite.add_variants` 机制，标记 `origin="hidden-final"`。
   - 只进 final 级别，不进入配对键（P02b 的 `scheduler/pairing.py` 只看 official 用例）。
3. **物理合理性检查**：出现以下任一情况，就把该用例标为 `implausible`：
   - 用时低于该用例的解析下限，即数据量除以设备峰值带宽；
   - 比该题此前最好成绩快出可配置的倍数，默认 3 倍，或超过历史最大提速的 2 倍。

   被标记的读数不计入门禁证据，直到在冷启动会话中复测、两次读数相差不超过 10%。峰值带宽取自 `config.json` 的 device 段，仓库里不写数值；未配置时只做倍数检查。

## R2 逐例的本地与评分端校准表

1. 每条规范回执都配对记录以下字段，持久化在 `results/<title>/.calibration-pairs.jsonl`，按 `submission_id` 去重：
   - 本地预测增量（相对同代基线）；
   - 本地噪声带；
   - 评分端增量；
   - 所用基线。
2. 每例、每题计算：
   - 符号一致率与秩相关；
   - 回退率：本地为正、评分端为负的比例。

   据此把每个用例标为 `trusted`、`noisy` 或 `divergent`。
3. 门禁返回预测分时附区间。只要涉及 `divergent` 用例，就在返回里标出，并把这些用例的贡献按「未知」处理，即放宽区间，而不是当作 0。额度不进任何阈值。
4. 先用磁盘上已有的回执回溯计算一次，报告结果。

## R3 噪声感知的保留与判定

1. 逐例三态判定：
   - 配对增量超出该例噪声带一定余量（可配置，默认 1%）为 improved；
   - 反向为 regressed；
   - 其余为 indistinguishable。

   测试摘要、P12 的 `per_case` 视图与账本 `experiment.outcome` 都使用这三态，不再把原始 µs 差值当作提升证据。
2. 重复样本的离散度（CV）超过阈值（默认 3%）的用例标 `noisy`，不计入增益声明，并在状态卡中标出。
3. 有 P10 的配对数据或 profiler 计时时，噪声带优先取它们给出的区间。P10 尚未合入 `main`，接口按 report 中的 `timing_source` 字段兼容即可。

## 验收

- 单测：
  - 计时归属的核对；
  - 未公开变体的确定性，且只在 final 生效；
  - 物理合理性检查的下限与倍数标记，以及冷启动复测后解除；
  - 校准表的去重与三类标签；
  - 门禁区间对 `divergent` 的处理；
  - 三态判定与 `noisy` 标记。
- 回溯报告：用现有回执算出校准表与标签，附各题回退率，写入 `docs/plan-4.1-4.2/reports/P17-calibration.md`。
- 真机：
  - 对一个已知通过的 SHA 跑一次带未公开变体的 final，确认没有误报；
  - 对 QuantScaleCalib 的 a2717b5 跑一次，看新增变体能否额外暴露问题。
