# ConcatD · `+8.14` pts (`46.29 -> 54.43`)

> **Code Provenance**: Core kernel & tiling breakthrough landed in `e9f921b` + `89e9e98` + `ea7e118` (built on `2dd9acd`'s UB Vector Gather assembly); submitted SHA `7919dcb` only guarded working directory in `validation/run-npu.sh` with identical `op_host/` & `op_kernel/`.

## 1. Context & Bottleneck
`2dd9acd` introduced UB Vector Gather whole-row assembly (`CONCATD_COPY_GATHER4/2/1`), slashing narrow unaligned shapes (`unalign_f32_w4`: `245.63 -> ~4 us`, 32-case `sum_med 1056.81 -> 185.17 us`, **5.71x**), yet **regressed online (`49.65 -> 46.29`)** because:
1. **Monolithic binary bloat**: compiling Vector Gather and Pure-DMA inside one `schMode=0` binary inflated code size, register pressure, and prologue cost (`aiv_scalar_ratio = 0.74–0.93` on pure-DMA cases `many64`, `small_1k_align`, `axismid`).
2. **Oversized tiling transfer**: `coreStart[40][2]` bloated `ConcatDTilingData` to `1704 B` on every launch and clamped `coreNum <= 40`.
3. **Suboptimal core scaling**: `MIN_CORES = 4` taxed `<= 16 KB` shapes (`small_1k_align 2.29 us`, `tiny32 4.69 us`), 40 cores on 2–4 MB shapes over-dispatched past Accel soc-a HBM saturation (`few_outer_2m 5.87 us`, `wide_row_4m 6.80 us`), while 1B `Gather1` was core-starved (`vec = 0.70–0.73`).

## 2. Core Breakthrough Mechanisms
1. **Multi-`schMode` Binary Isolation + `static __attribute__((noinline))` Specialists**:
   - `CONCATD_TPL_SCH_MODE_0` compiles **only** pure-DMA specialists (`RunFlat1`, `RunImage32`, `RunGeneralRows`, `RunGeneralRange`) with zero vector/Gather code in icache.
   - `CONCATD_TPL_SCH_MODE_1` compiles **only** `RunGatherWord<uint32_t|uint16_t>` and `RunGatherByte`, further pruned by `if constexpr (sizeof(DTYPE_X))`.
2. **64 B Cacheline Tiling Payload (`SetDataSize`) + `sameWidth` `O(1)` Lookup**:
   - Dropped `coreStart[40][2]` (`1704 B -> 1064 B` struct); placed 40 B header + `widths[0..2]` in cacheline 0 and trimmed host->device DMA via `rawTiling->SetDataSize(actualBytes)` to **64 B** whenever `count <= 3` or `sameWidth == 1`.
   - `LoadMetaToUb` uses `DataCopyPad` only when `(!sameWidth && count >= 8)` or `count >= 16`; `RunFlat1` jumps straight to the starting input via `start / w0` when `sameWidth`.
3. **`CONCATD_COPY_FLAT1` Single-Shot UB Coalescing & 1-Input Collapse**:
   - Collapses single active non-zero input (`nonZeroCount == 1`) to `outer = 1`.
   - For `outer == 1 && aligned32 && sliceBytes <= 32 KB`, `RunFlat1` loads all overlapping input segments into one `32 KB` UB stage (`s0`) with a single `MTE2_MTE3` sync and **one contiguous `DataCopyPad` store**.
4. **HBM-Saturation Piecewise `blockDim` Scaling**:
   - `totalNum <= 16 KB && count < 8` -> `1 core`.
   - Pure DMA ramp: `<= 512 KB -> max(2, ceil(N/64KB))`; `<= 2 MB -> max(8, ceil(N/96KB))`; `> 2 MB -> max(22, ceil(N/256KB))` (matching ~22 AIV HBM saturation knee).
   - `Gather1` (1B odd widths) uses `16 KB/core` (2x cores); `GatherWord` uses `64 KB/core`.
5. **UB Vector Gather Whole-Row Assembly (Isolated in `SCH_MODE_1`)**:
   - Contiguous `nrows * w` `MTE2` loads, `O(log2)` Level-0 `Add/Adds<int32_t>` offset doubling, `Gather<u32|u16>` (or for 1B odd widths: `ShiftRight<u16>(8)` -> dual even/odd `Gather<u16>` -> `And(0x00FF)` + `ShiftLeft(8)` -> `Or`), double-buffered across `stage0/1` + `out0/1`.

## 4. Precision & Synchronization Invariants
- Bit-exact (`0/8` sample, **`90/90` isolated extended cases** across fp32/fp16/bf16/int8/int64, all axes, zero-width & unaligned inputs).
- Pure DMA uses explicit `MTE2_MTE3` + `MTE3_MTE2` hardware events (not `TQue`, which omits reverse `MTE3 -> MTE2` sync on pure copies). Gather paths use explicit `V_MTE2`/`MTE2_V`/`V_MTE3`/`MTE3_V` with full drain waits and `S_V` after scalar index seeding.
- **Multi-TU linker invariant (`ea7e118`)**: every `__attribute__((noinline))` specialist defined in a header compiled into multiple `schMode` TUs must be `static`, otherwise fatbin linking fails on duplicate symbols.
- `WS_SYS_SIZE = 4096 U` kept non-zero (`0` triggers online `cpu_timeout`).

## 5. Reusable KernelC Pattern
> **Rule (`tiling-regime`)**: Isolate heavy vector/gather specialists into a separate `schMode` `tilingKey` using `static __attribute__((noinline))` functions so pure-DMA paths keep minimal icache/register pressure; trim host->device tiling payloads to 64 B with `rawTiling->SetDataSize()`; and cap pure-DMA `blockDim` at the SoC's HBM saturation knee (~22 AIV cores on soc-a at 2–4 MB) with 1 core below 16 KB.
